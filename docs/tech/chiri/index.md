## 1. What We Are Building, Technically

One page, loaded once, holding one document that never leaves the browser profile it was typed in.
The page owns an editing surface whose in-memory representation is the Markdown source text itself, painted so it reads as prose; two overlay layers draw text that is not in the document (a proposed continuation at the caret, a proposed rewrite over a selected span); a scheduler decides when a network call is allowed to leave; and a streaming client talks to exactly one external endpoint.
A keystroke touches only the editing surface and a debounced write to local storage - it never waits on the network.
When the writer pauses, the scheduler waits for input to settle, sends one request, and cancels it the instant the writer types again or moves the caret.
Nothing that has not been explicitly accepted by the writer is ever inside the document, so it can never be saved, exported, or restored.

## 2. Deployment Tier and What It Buys Us

Tier is `local`, given explicitly and corroborated by every structural signal in the PRD: no backend (A-2), no accounts (Non-Goal 3), no server-side persistence or sync (Non-Goal 10), no telemetry (Non-Goal 9), one document scoped to one browser profile (A-7).
The one datum that leaves the machine is the user's own OpenRouter key, sent only to OpenRouter.
"Local" here means the app is run by whoever built it or by an evaluator handed the repo, started with one command, and never put on a URL a stranger can reach.

What this tier deliberately does not include, and what would force an upgrade:

| Shortcut | What it costs | What forces the upgrade |
|---|---|---|
| The API key sits in `localStorage` in plaintext, readable by any script on the origin. | Any XSS, including a malicious transitive npm dependency, exfiltrates the key. No rotation, scoping, or expiry. | Any public URL, or accepting a key belonging to anyone but the person running the page. The key then has to move behind a backend, which voids A-2 and this whole design. |
| No CI, no automated cross-browser run, no pipeline lint gate. The NFR-7 four-browser check is a manual pass. | Safari- and Firefox-specific breakage in ghost text, bar placement, or stream abort is found late, by a human. | A second contributor, or distribution to anyone not in the room. |
| No error reporting, telemetry, or crash capture. This is required by NFR-3/NFR-4, not merely permitted by the tier. | Every failure is invisible unless someone is watching the console when it happens. | Nothing infrastructural. If diagnosis becomes necessary the answer is a local-only debug panel behind a flag, never a reporting service. |
| No service worker. Offline degradation is no longer a stated requirement - the PRD's NFR-8 was removed rather than implemented - so the app is network-dependent at boot by design, not by omission. | Closing the tab offline and reopening it yields nothing, even though the document is safely in IndexedDB. Nothing in the test suite covers or flags this. | A product decision to promise offline again. Roughly a day of work: a precache service worker over the built assets. |
| One tab only. The document lives under a single IndexedDB key written by a debounce, and nothing coordinates two tabs on the same browser profile. | Two open tabs clobber each other last-writer-wins, with no warning and no merge. It is worse than it sounds: `visibilitychange: hidden` fires exactly when the user switches tabs, so switching away from tab A flushes A's stale text over whatever B wrote. | Any use where a second tab is plausible - which starts the moment the app is on a URL rather than run by the person who built it. The fix is a `BroadcastChannel` or a Web Locks leader election plus a "this document is open in another tab" state, roughly a day, and it needs a product answer about what the non-leader tab shows. |
| No retry with backoff. Revision failures get one user-pressed retry button; rate-limit recovery is the token bucket refilling, not `Retry-After`. | A sustained provider 429 looks like continuation silently stopping, which AC-12.3 tolerates but which is indistinguishable from a bug. | Continuation observed stalling for more than a few seconds during a normal session. |

## 4. How It Fits Together

One runnable piece: a static single-page app, `npm run dev` in development, `npm run build && npm run preview` for the built artifact.
There is no server, no build-time secret, and no deployed service.

Inside the page, five parts talk only in-process:

**The editing surface** owns the one document as Markdown source text, styled in place by a live-preview decoration plugin.
It exposes three things to everything else: an overlay that paints text not in the document at the caret, an overlay that paints a diff over an arbitrary character range, and screen coordinates for the current selection.

**The pending-AI layer** holds all unaccepted output - ghost continuation and pending revision alike - as CodeMirror `StateField` decorations, never as document text.
This is structural, not stylistic: because unaccepted text is physically incapable of being in the document, AC-4.3, AC-5.6, AC-9.5, and AC-6.16 (no pending output persisted, exported, or restored) hold by construction instead of by remembering to filter in four call sites.
Accepting commits the text in a single transaction, which is what makes AC-3.3/AC-5.9/AC-6.8 one undo unit.

**The request discipline layer** sits between "something happened in the editor" and "a call goes out".
It owns settle detection (starting at 600ms), a ceiling of one in-flight continuation, a token bucket of 20 continuations per minute, and a caret-generation guard that voids a response whose anchor no longer matches.
Revision and refinement requests bypass it entirely and are never dropped (FR-10).
The concurrency slot is released synchronously at `abort()` rather than at stream close, because probe 3 showed the socket really does close on abort in all three tested engines - holding the slot until the stream drains would throttle the writer for no reason.

**The provider client** calls the one external endpoint with `stream: true` and parses SSE lines off the response body reader.
Revision and refinement responses stream as plain text in two parts: a single reason line, a sentinel line, then the proposed replacement text, parsed incrementally.
JSON mode is rejected because a JSON object cannot be rendered until it is nearly complete, which spends the whole NFR-1 budget before anything is visible.
A second reason - that structured-output support varies across the models FR-8 lets the user pick - is an unverified belief, not a probe result; check it against OpenRouter's model catalogue when the curated list is fixed (open question 3), and if support is universal this rejection still stands on the latency argument alone.

**The chrome** is React: launch mark, key gate, model selector, selection-anchored action bar, revision accept/reject/refine controls, failure messages, export.
The CodeMirror instance is mounted once into an uncontrolled div and deliberately kept out of React's render path; the two communicate through the Zustand store, read reactively by React and imperatively by CM6 plugin code.
Probe 5 established that plugin code cannot call `useContext` at all - a `ViewPlugin` is a plain class CodeMirror constructs outside React's render cycle, so there is no hook dispatcher at that call site - and that a constructor-captured value goes stale, while a ref kept current by an effect reads live.
That makes the store's read side a pull, and pull is enough here by design: every cross-cutting field the plugin reads (continuation on/off, selected model, API key) is consumed at the moment the next request is assembled, and an edit is what triggers that assembly, so the plugin never needs to be woken by a change it did not already ask about.

### The request contract

What is sent is as load-bearing as what comes back: it sets per-request cost on the user's own key and it is the main lever on NFR-1.
It is built by `src/core/prompt.ts`, a pure string-in, string-out module, so these numbers are tunable in one place if the measured NFR-1 margin in section 8 turns out to be thinner in practice than it was on the developer machine.

| | Continuation | Revision and refinement |
|---|---|---|
| Context sent | The 2,000 characters of document text immediately preceding the caret, trimmed forward to the nearest paragraph break so the prompt never starts mid-sentence. Nothing after the caret. | The selected span verbatim, plus the paragraph before and the paragraph after it as unmodifiable context, each labelled, plus the user's refine instruction when present. |
| System message | Fixed, held in `prompt.ts`. States the two-sentence ceiling, forbids preambles and quoting, and forbids restating text already present. | Fixed. States the reason line, the sentinel line, and that only the span may be rewritten (AC-6.9). |
| `max_tokens` | 120 | 400 |
| `temperature` | 0.4 | 0.2 |
| `stream` | `true` | `true` |

No other request parameter is set, so per-model defaults apply.
The whole document is never sent, at any size, which keeps request cost flat as the document grows toward the 20,000-character ceiling in section 5 and keeps the prompt near the ~1,500-token shape probe 2 actually measured NFR-1 against.

### Live-preview marker hiding, as corrected by probe 4

Heading marker ranges are `Decoration.replace` ranges **manually extended by one character to swallow the space after the `#`**, because probe 4 found Lezer's `HeaderMark` token stops before that space and a naive replace leaves a dangling space artifact.
Probe 4 walked `HeaderMark` only.
Whether `EmphasisMark` and list marks need the same extension is unverified, and for `**bold**` they almost certainly do not, since those markers have no trailing space and blindly extending would eat a real document character - so each node type gets its range checked against the rendered line when it is added, rather than inheriting the heading rule.
The same range set is additionally fed to `EditorView.atomicRanges.of(view => plugin.decorations)`.
This facet is not optional: without it, probe 4 measured `ArrowRight` landing the caret at position 3, strictly inside a hidden `# ` span, an invisible dead stop; with it the caret steps 2 to 4 in one press.

The active line reveals its raw markers, and **the line visibly shifts horizontally when the caret lands on it**.
Probe 4 confirmed the rendered line content goes from 12 to 14 characters, so the markers are real text nodes and the shift is structural.
The spec says "markers hide and the active line shifts a little when you land on it", not "seamless".
Scope of live preview is fixed up front: hide markers for headings, bold, italic, and links only; code fences, blockquotes, and horizontal rules keep their syntax visible.

## 5. Data

One document, one settings blob, both local to the browser profile.

| What | Where | Shape | Write schedule |
|---|---|---|---|
| Document | IndexedDB, one key via `idb-keyval` | `{ text: string, caretOffset: number, savedAt: number }` | 800ms debounce, forced flush on `pagehide` and `visibilitychange: hidden` |
| Settings | `localStorage` | `{ apiKey: string, model: string, continuationEnabled: boolean }` | Immediate on change, read once at boot |

Persistence is reached only through a `DocumentStore { load(): Promise<Doc|null>; save(doc): Promise<void> }` interface and a matching `Settings` interface, so the storage engine is swappable and fakeable.

No migrations: there is one schema version, one document, and no other installation to be compatible with.
If the shape ever changes, boot reads the old key, converts in memory, and writes the new one - a function, not a framework.
No backups: the tier does not pay for them, and Markdown export (FR-9) is the documented escape hatch, which the PRD already treats as the durability story (A-7).

The 20,000 characters named by NFR-2 is the practical ceiling; nothing here is designed for a 500KB document.

## 6. Testing Seams

Split out because it is written for a different reader than the rest and has to stand alone: [Testing Seams](./testing.md).
The pure core is five dependency-free modules under `src/core/` (scheduler, continuation eligibility and sanitizing, revision reducer, SSE and error parsing, prompt and context assembly), fenced off by an oxlint `no-restricted-imports` override scoped to `src/core/**/*.ts`.
That rule was verified to fire, not assumed: a planted `import { useState } from 'react'` in `src/core/` produced `error eslint(no-restricted-imports)` with the configured message, and was removed.
Every external dependency - the OpenRouter transport, the clock, IndexedDB, `localStorage` - is behind an injected interface, and CodeMirror is never faked: anything touching the `EditorView` runs in a real browser under Playwright, because probe 4 showed jsdom needs hand-written polyfills to boot CM6 and still has no layout engine.
The first failing test was `src/core/schedule.test.ts` asserting AC-10.2, it needed nothing running, and it is now written and passing alongside five more over the same module.
That is the scheduler satisfying its assertions in isolation, not FR-10 shipped: it is wired to no editor, has no transport behind it, and AC-10.5's persistence across reloads is unbuilt.

Findings that changed the design:

- Finding 1 removed the local dev proxy from consideration and closed the load-bearing CORS assumption behind A-2 as measured rather than assumed.
- Finding 2 closed NFR-1 as measured rather than assumed, kept `openai/gpt-4o-mini` as the pinned default (owner decision: it clears the bar, and this is a single-user proof of concept), and named `openai/gpt-4.1-nano` as the latency lever in section 7 instead of a prompt or client change. Its Gemini 404 added an endpoint-access check to open question 3.
- Finding 5 demoted Zustand from a requirement to a preference in section 3, downgraded its reversibility from `costly` to `trivial`, and put the pull-versus-push reasoning in section 4 rather than leaving the dependency justified by a claim that is now false.
- Finding 3 changed the scheduler to release its concurrency slot synchronously at `abort()` instead of at stream close, and its same-origin/WebKit-build caveat is why the generation counter guard in the provider client exists and stays.
- Finding 4 added `EditorView.atomicRanges` as a required part of the live-preview plugin, extended the *heading* hidden range to swallow its trailing space (the only node type probe 4 walked - emphasis and list marks remain unchecked), and changed the spec language from seamless hiding to an acknowledged horizontal shift on the active line. It did *not* force the fallback to dimming markers instead of hiding them.
- Finding 4's jsdom polyfill burden is why Playwright, not Vitest, owns every test that touches the `EditorView`.

## 10. Assumptions

| Assumption | What breaks if it is wrong |
|---|---|
| The toolchain runs on the development machine's Node 26.4.0; the minimum Node the Vite 8 / TypeScript 6 / Vitest 4 toolchain actually supports has not been checked. | Tooling setup only, nothing in the design - but a contributor on an older Node hits an install or build failure the document did not warn them about. Read the engines field of the installed toolchain before assuming a floor. |
| "Local" means the app is run by whoever built it or an evaluator handed the repo, never placed on a reachable URL. | The plaintext key in `localStorage` becomes an exposure rather than a shortcut, and section 2's upgrade trigger fires immediately. |
| The design-preview HTML in `docs/design-preview/chiri/` is a visual reference for chrome only and carries no authority over the editor's internal DOM. | If the mockup's editor markup is treated as a spec, it conflicts with CM6's own DOM and the live-preview plugin has to be rebuilt around it. |
| The practical document ceiling is the 20,000 characters NFR-2 names. | Above roughly 100KB, the whole-document debounced write and the decoration rebuild strategy both need revisiting, and open question 5 becomes urgent rather than routine. |
| The user's OpenRouter key is a personal key with credit on it; rotation, scoping, and spend limits are the user's own concern (Non-Goal 8). | A shared or org key makes the plaintext storage a third party's problem, which the tier does not cover. |
| Exactly one tab has the app open at a time. Nothing detects or coordinates a second one. | Two tabs silently overwrite each other's document, last writer wins, and the tab-switch flush makes it likely rather than rare. Recovery is whatever the user last exported. The fix is leader election plus a non-leader state, which is a product decision as much as a technical one. |
| The measured NFR-1 latency generalises from Node on the developer's machine to a browser on the user's network. | Continuation feels late even though the design is unchanged. The response is the model lever in section 7, not a code change, because probe 2 showed the cost is time-to-first-byte. |
| Probe 3's WebKit result generalises to Safari.app well enough to ship against. | Cancelled continuations keep streaming on Safari; the generation counter contains the damage but wasted spend and a stuck-feeling slot appear until the release path is guarded. |
| Provider failures map cleanly onto the small failure-class set the PRD defines (auth, credit, rate limit, network, malformed). | An unmapped shape falls through to a generic message, which AC-12.6 tolerates but which makes the first-run key mistake harder to diagnose. |

## 11. Getting Started

1. Before writing app code, abort a real cross-origin OpenRouter stream mid-flight in Safari.app, Chrome, and Firefox by hand. That is the one transport question still open. CORS is settled by probe 1 and NFR-1 latency by probe 2; do not re-litigate either.
2. Done, do not redo it. The Vite react-ts scaffold exists with every dependency in section 3 installed, `src/core/` created, and the oxlint `no-restricted-imports` override scoped to `src/core/**/*.ts` blocking `react`, `react-dom`, `react/*`, `@codemirror/*`, `zustand`, `idb-keyval`, and `@floating-ui/*`. `npm run build`, `tsc -b --noEmit`, oxlint, Vitest, and Playwright all run clean, the last over 4 scaffold-verification specs in `e2e/editor.spec.ts` that are not part of [testing.md](./testing.md)'s seven-spec inventory. Read `.oxlintrc.json` before adding anything to `src/core/`.
3. Done as a module. `src/core/schedule.ts` exists with 6 passing Vitest tests, including the AC-10.2 assertion [testing.md](./testing.md) names as the first failing test. FR-10 is not finished: the scheduler is wired to no editor, has no transport behind it, and AC-10.5's persistence across reloads is unbuilt. The wiring lands in step 6, the transport in step 7, and the settings write that carries the toggle across reloads alongside the other `localStorage` scalars in section 5.
4. Build the editor spike: CM6 in an uncontrolled div, `lang-markdown`, and the live-preview plugin with `atomicRanges` wired and trailing spaces swallowed. Type a document containing every FR-3 construct, including nested emphasis in a list item in a blockquote. Measure open question 5 here. Do not proceed until Markdown reads as prose and arrow keys behave.
5. Wire persistence: `DocumentStore`, the `idb-keyval` implementation, the 800ms debounce on an injected clock, and an explicit `flush()` called by a thin `pagehide`/`visibilitychange` listener. Answer open question 6 while you are here. FR-4 is done before any AI exists.
6. Add the ghost-text `StateField` and widget driven by the scheduler, against a fake transport returning a canned string after 400ms. Get accept-full, accept-word, dismiss-by-typing, dismiss-by-caret-move, and single-unit undo working entirely offline, and settle open question 7 in the same sitting.
7. Swap in the real streaming client, with `src/core/prompt.ts` building the request and the response sanitizer parsing it back, both pure.
8. Then FR-6: selection-driven action bar via `floating-ui`, the revision reducer, the diff decoration set with `RangeSet` mapping, accept as one transaction, invalidation on in-span edits.

"It works" for the first slice: with devtools set to offline, you can type a full Markdown document with headings, lists, and a code block, it reads as prose rather than source, and reload restores it exactly with the caret where you left it, showing no error anywhere.
Turn the network back on, pause mid-sentence, and grey text appears while you are still pausing - the SC-2 judgement the PRD actually uses - that Tab takes and Ctrl+Z removes in one step.
Probe 2's measured expectation on the default model is roughly 0.7s at the median and 1.6s at the worst of ten runs, so a wait that reads as a stall rather than a pause means something is wrong beyond the provider.
