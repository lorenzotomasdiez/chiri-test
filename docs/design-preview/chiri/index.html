Requirements with no screen

These were deliberately left unillustrated. The reasons are below.

FR-4

Local persistence is an invisible background behavior (autosave with no save button, no saving indicator specified). Its only user-visible evidence is that the document and caret position are already restored when the editor screens load, which is captured as the default state on the onboarding and continuation editor screens rather than a screen of its own.

FR-10

Request debouncing, cancellation of stale continuation requests, and concurrency/per-minute ceilings are explicitly silent server-side/client-side discipline with no visible UI beyond the existing on/off toggle for continuation, which is already shown as a control on the editor-continuation screen.
